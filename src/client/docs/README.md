# Web 界面

React 19、Tailwind 4，原有 hash 地址继续兼容。首页直接进入排班；桌面主导航和手机底部导航只保留排班、人员、导入。管理通过桌面侧栏或账号菜单进入。

- 排班：日期/部门/名称筛选、缺员过滤、CSV 导出、安排工作、任务与公平账本视图。任务详情、候选和已安排人员在侧栏处理。
- 安排工作：同一表单填写名称、部门、日期、起止时间、人数，可按周重复。缺少学期或人员时可在侧栏补建并返回原草稿。
- 人员：点击姓名查看课表和请假；原资料编辑、部门与成员关系继续保留。
- 导入：统一材料入口，浏览器本地 Agent 整理后按组织、人员课表和任务班次复核；支持暂停恢复、来源查看和一键提交。
- 管理：规则、学期、模型服务、账号授权、审计分区。
- 模型服务：models.dev 目录、图片能力过滤、勾选模型、粘贴加密密钥、启停、测试、拖拽及按钮排序。浏览器 Agent 按全局顺序选择支持视觉及工具调用的模型，失败切换下一项；旧单文件兼容接口仍保留独立默认模型语义。

主题遵循根目录 DESIGN.md，可手动切换并保存偏好。Inter 自托管，许可证随字体分发。

## 验证

先启动隔离的本地数据服务和 `pnpm dev`，再运行 `pnpm test:browser`。浏览器测试会创建测试学期/部门/人员和班次，只可指向隔离本地数据。测试截图和报告已忽略，不进入生产构建。


### 模型配置草稿与排序

模型服务使用本地草稿与统一保存栏；新增和密钥更换先加入草稿，支持抓手/触屏/键盘排序。@dnd-kit 负责传感器、排序位置与拖动覆盖层，Tailwind 仍负责页面样式。


模型连接测试相互独立，不阻塞其他测试或配置编辑、排序、保存。测试使用已保存配置，结果位于对应模型卡片内；失败展示 HTTP 状态、上游代码/类型和可滚动的完整错误正文（敏感信息脱敏），不占用页面顶部错误区域。

## 人员对象导入

导入采用 ImportSession + m 个 PersonWorkspace。协调器分派来源并维护公共日历，子智能体只填写和复核本人的 A/B；默认最多8个人员并行（模型请求自适应限流），失败隔离、检查点恢复、已完成人员复用。全批完成后由唯一投影逻辑匹配身份，生成按学期/明确周次覆盖的差异，审核确认后提交。

客户端 `person-runner.ts` 负责对象执行，`projection.ts` 负责共享草稿，`runtime.ts` 负责人工编辑和提交，`state.ts`/`store.ts` 负责状态和持久化。原有文件解码、OCR、图片预算、来源覆盖、领域展开与提交事务继续复用。旧版全局对话、交接和通用 CRUD 工具已删除。

Worker `llm/agent.ts` 保留已有 AI SDK 与供应商适配，只开放 discover/person/verify/consistency/reconcile 对应的工具。人员不能写公共日历或他人对象。前后端需同步发布，无新增依赖、环境变量或业务迁移。旧版未完成批次原件保留，重新导入后使用新执行器。

验证：`pnpm check`、`pnpm test:agent-browser`、`pnpm build`；人员专项 `pnpm test:agent-person`。浏览器测试拦截模型，不代表真实识别或耗时已验收。完整契约、恢复与覆盖边界见根目录 `docs/AGENT_IMPORT.md`。

局部返工可按课程索引指定重查范围；来源不变且此前已独立核实的其他条目可复用，新增来源仍全量复核。指定重查条目必须重新提交原件事实，最终检查整表一致性；详见本模块架构。无新增依赖或部署配置，前后端工具协议同步发布。

跨人核对新增 consistency 模式：待核对差异不少于两组时，按既有每批最多5组/通常8份来源划分，最多4个独立读取对象并行。各对象只可读取、保存本批核对结论或向本批涉及人员提出返工；不能修改日历、分派人员或交付导入。结论完成异步来源检查后合并检查点，避免并发覆盖。所有读取结束后按人合并返工说明、来源与重查索引；任一要求全量复核则合并为全量，不截断说明。部分失败保留已完成结论、待返工意见与未完成上下文，恢复不重跑已完成批次；暂停须等待在途请求结束，未执行工具可在刷新后继续。当前事实签名变化时丢弃过时读取任务，操作员新意见取消旧待执行意见。最终仍由协调器核对全局身份、日历、全部差异和提交条件，不减少检查组或放宽来源门槛。材料缺失/错放说明保留在各批上下文，避免遗漏跨目录证据。无新增依赖、环境变量、配置或迁移；前后端工具协议须同步构建发布。

人员完成独立复核、或并行核对批次完成且没有待执行工具后，活动 AgentState 中的图片字节替换为可追溯的来源引用；保留工具消息、来源覆盖、独立观察值、核对结论和原件。未完成对象仍保留所需图片，后续人员返工会重新读取原件。避免已完成图片在每次全批检查点复制中重复占用内存与传输；不删除原始材料，不提前接受未完成复核。无新增依赖、配置、环境变量或迁移。

人员完成门槛提前检查同一课表内可落库课程的重复键（名称、星期、起止节次及去重排序后的周次；教师/地点差异不构成另一场课）。重复时反馈原索引，由模型按原件合并并重新独立复核，不自动删除。含未知星期/节次/周次的条目必须标记partial且在该课表unresolved保留待补说明，继续要求明确replace_weeks；防止人员宣称complete后才在提交时被拦截。正式提交校验不变，无新增依赖、配置、环境变量或迁移。

跨人分批仍最多5组、通常最多8份不同来源；单组不可拆分而已超过8份来源时，后续组若完全复用当前来源，可同批核对，不重复开启相同图片的读取对象。新增来源仍会触发批次边界，全部差异与原件检查不减少。无新增依赖、配置、环境变量或迁移。

人员全部完成后，跨人核对前检查已复核的零课程missing方案：仅当原件明确姓名唯一、对应已完成人员也唯一、来源属于该缺失方案且目标尚未读取时，将其作为补充来源送入目标人员的全量独立复核。不会转移课程、修改身份或填补缺失人员课表；无姓名、重名、多姓名或未完成检查仍交协调器处理。已分派来源不会循环返工，自动分派写入工具记录；目标新增来源不复用旧独立观察值。工具说明明确错放原件的实际姓名仍应填写，不能用目录名猜造。无新增依赖、配置、环境变量或迁移。

明确错放来源的交接在人员队列运行过程中调度：来源方与唯一目标都已完成且没有在途工具时，将目标加入同一有界队列，可与其他人员并行。分派操作串行化，防止两个完成回调重复替换同一目标；正在处理的人员不改写，重名判断仍包含活动对象。暂停不启动新工作；失败等待所有在途任务结束，新增交接对象也纳入完成检查。独立复核、来源唯一匹配及整体提交门槛不变。无新增依赖、配置、环境变量或迁移。

最终协调上下文新增紧凑的完成摘要：每份课表列出来源路径、已保存的无固定时段课程名称，以及已完成对象的独立复核覆盖、条目数、已读来源和原件姓名/学号；未完成对象不声明已验证。只提供事实签名仍有效的跨人结论key、处理结果和说明，帮助协调器识别已完成工作；不展开全部课程，不改变人员独立复核中隐藏首次识别值的规则。新证据或未解决矛盾仍可返工，最终检查门槛不变。无新增依赖、配置、环境变量或迁移。

当前教师差异按教学情境筛选，取代此前仅按课程同名触发复核的规则：已明确不同班级、不同绑定学期，或星期/节次/教学周明确不相交时，不因教师不同产生冲突。仅参与至少一对可比较教师差异的变体进入复核；班级或时段未知不能据此排除，重叠区间按实际交集检查。同一人员分时段由不同教师授课亦可合法。不会改写任何课程或统一教师，各人员仍逐项独立回看原件；候选差异继续需要来源核对和结论。变体包含课程时段事实，相关时段变化使旧检查点失效。只按已有结构字段判断，不解析目录名猜班级或学期别名；不凭未绑定的学期名称断定不同学期。无新增依赖、配置、环境变量或迁移。

独立复核的reuse_verified_entries标记在没有旧观察值时视为空的复用集合，仍保存本次提交的新观察值；随后继续检查所有索引、全部课程字段、身份和覆盖范围。缺项或不一致仍拒绝完成，但已读出的值可以用于下一次补交/修正，不再因不存在旧缓存而丢失。不会复制首次提取值、自动改课或放行部分检查；新来源仍清空旧轮观察值。无新增依赖、配置、环境变量或迁移。

## 导入界面与外壳（2026-11-08）

页面只显示标题，不再显示副标题。页眉为搜索框（窄屏仅图标）、明暗图标按钮和头像账号菜单；侧栏去掉标语。

导入页按用户任务分为三态：
- 空闲：大面积拖放区（拖入时图标抬起并变色）+ 最近导入列表（状态胶囊、已结束批次可一键清理）+ 折叠的已提交记录。
- 处理中：四步进度条（识别材料 → 逐人整理 → 交叉核对 → 复核导入，当前步脉冲、完成步打勾、连线填充），一行实时状态（当前动作、请求已等待秒数、人员完成数/课程数）和最近一次模型调用的切换链（失败红色、成功绿色）；人员卡片显示状态与进度条，处理中带扫光，识别阶段用骨架卡占位。“暂停”点击后立即显示“正在暂停”直到运行器停下。
- 复核：人员卡片只保留失败或需确认身份的人；复核内容统一为卡片与绘制的折叠箭头；底部吸附操作栏包含给 Agent 的一句话修改（Enter 发送，发送中显示加载）与“确认导入”，阻止提交的问题列在操作栏上方。

模型请求、步骤日志与完整工具记录收进一个“运行记录”折叠面板，按标签切换。动画定义在 `index.css`（`rota-ping`、`rota-shimmer`、`rota-pop`、`rota-enter`），`prefers-reduced-motion` 时全部关闭。组件位于 `agent-import/Progress.tsx` 与 `HistoryPanel.tsx`。

## 导入执行效率与实时反馈（2026-11-08）

- 文档工具：取消全局串行队列。解析使用可复用 Worker 池（2–4 个，按 CPU 核数，超时或崩溃才替换，空闲 60 秒回收），主线程画布渲染最多 2 个并行；结果按（文件、大小、动作、参数）在内存 LRU 缓存约 150 MB，同一共享表格/页面在多人、复核和补跑间只解析渲染一次，进行中的相同请求共享同一 Promise，失败不缓存。材料覆盖记录与解包写入在提交锁内基于最新记录读改写，避免并行读取互相覆盖。OCR 不再占用文档队列。
- 模型请求：新批次人员并发上限 8（旧检查点保留原值）。模型请求另有自适应窗口：从 4 开始，满窗口成功后加 1，至多到批次上限；超时、429、503、504 时减半（30 秒内只减一次），最少 1。等待窗口时人员卡片显示“排队等模型”。
- 传输：每请求内联图片总预算 8 MB，重试时逐次减半；相同图片只保留最后一次。连续失败只保留一条“上一请求未返回”提示，不重复追加。浏览器超时为 130 秒加按 100 KB/s 估算的上传时间（最多再加 170 秒），超时文案不含接口路径。
- 检查点：`persist` 合并写入，同一时刻最多一次 IndexedDB 写入，其间的修改合并为下一次写入；界面刷新节流为 200 ms。
- 实时状态：`Job.activity` 记录每个人员/核对对象/协调器当前动作与开始时间（读取材料、排队等模型、等待模型、渲染表格、稍后重试、排队重试等），运行结束清空。
- 界面：人员概览改为分段进度条（完成/处理中/等待重试/失败/排队）与计数；模型按名称汇总成功/失败次数。人员卡片显示姓名与班级标签、按本轮已读来源比例计算的真实进度、当前动作与计时、简短错误（原文在悬停提示与详情）；补跑前显示琥珀色“等待重试”。点击卡片展开详情：错误原文、来源读取状态、模型调用耗时和该人员步骤日志。批次标题栏滚动时吸附在顶部，暂停按钮始终可见。步骤日志中失败或超时的工具调用标红并附原因。
- 慢链路（生产实测到 Cloudflare 下载约 20–25 KB/s）：`public/_headers` 让带哈希的 `/assets/*` 永久缓存（immutable），`/vendor/*`（OCR 引擎与语言包约 10 MB）缓存 7 天并后台重验证，`/fonts/*` 缓存 30 天。文档 Worker 在池内只下载一次 7z wasm（`wasmBinary` 复用），不再每个压缩包重新获取。运行开始即保存“处理中”并显示协调器动作（准备材料、解包材料、读取材料），解包较慢时界面不再停留在旧的“已暂停”。首次使用 OCR 仍需下载约 10 MB 语言数据，慢链路下首个 OCR 可能超时，之后走缓存。
