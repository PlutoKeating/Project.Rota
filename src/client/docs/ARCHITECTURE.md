# 前端架构

`AuthGate` 提供 Session context；`Layout` 负责固定页眉、导航、账号菜单、主题及独立滚动内容区。`QuickSearch` 搜索人员与任务。`App` 保留旧路由兼容，首页渲染 SchedulePage。

`Modal` 统一侧栏与对话框，使用 portal、顶层窗口栈、inert、焦点循环及关闭后恢复焦点。嵌套配置不得让底层窗口处理 Escape。

`WorkComposer` 只提交 `/work`，服务端原子创建任务和全部重复班次。班次候选始终请求 `/preview`；正式分配单独确认。批量预览显示整个任务当前各班次缺口和候选数量，确认时服务端逐次检查，预览不承诺最终人数。

`ModelsPage` 读取 `/admin/model-config` 快照，所有新增、启停、删除、密钥替换和排序仅写当前组件内存草稿。保存栏显示未保存状态，点击保存后一次 PUT 整页配置；失败保留草稿，放弃更改重新读取服务端。未应用的添加或密钥输入会阻止保存，避免漏存。保存期间禁用编辑。已有模型可随时测试已保存配置，测试按模型 ID 独立管理 pending/result，不使用全局 busy，不阻塞其他测试、编辑、排序、删除或保存。新增模型需先保存。测试结果留在对应卡片下，并注明测试时的已保存配置。密钥不进入浏览器持久化；API 只返回 hasKey。

排序使用 @dnd-kit 的 PointerSensor、KeyboardSensor、SortableContext 和 DragOverlay；仅 44px 抓手启动拖动，其他区域仍可滚动/选字。相邻条目用 280ms transform 弹性让位，放下动效同速；新草稿行用 220ms 入场。系统减少动态效果时取消空间动画。保留上移/下移按钮和中文读屏提示。beforeunload、hash 路由和管理 tab 切换在有草稿时提醒放弃。

页面状态与网络状态通过现有 useAsync 管理。日期范围保存在 sessionStorage；侧栏操作保留底层页面筛选和滚动上下文。明暗主题保存在 localStorage。没有引入新路由框架或组件框架。

## 人员对象导入

导入采用 ImportSession + m 个 PersonWorkspace。协调器分派来源并维护公共日历，子智能体只填写和复核本人的 A/B；默认16个人员并行，失败隔离、检查点恢复、已完成人员复用。全批完成后由唯一投影逻辑匹配身份，生成按学期/明确周次覆盖的差异，审核确认后提交。

客户端 `person-runner.ts` 负责对象执行，`projection.ts` 负责共享草稿，`runtime.ts` 负责人工编辑和提交，`state.ts`/`store.ts` 负责状态和持久化。原有文件解码、OCR、图片预算、来源覆盖、领域展开与提交事务继续复用。旧版全局对话、交接和通用 CRUD 工具已删除。

Worker `llm/agent.ts` 保留已有 AI SDK 与供应商适配，只开放 discover/person/verify/reconcile 对应的工具。人员不能写公共日历或他人对象。前后端需同步发布，无新增依赖、环境变量或业务迁移。旧版未完成批次原件保留，重新导入后使用新执行器。

验证：`pnpm check`、`pnpm test:agent-browser`、`pnpm build`；人员专项 `pnpm test:agent-person`。浏览器测试拦截模型，不代表真实识别或耗时已验收。完整契约、恢复与覆盖边界见根目录 `docs/AGENT_IMPORT.md`。

复核工具 `finish_person.checks` 使用显式数组，每项包含课表 `key` 和字段核对结果；不使用动态键字典，以确保 Google 工具 schema 保留核对字段。对象持久化与正式审核报告仍按课表键保存检查结果，无新增依赖、环境变量或数据库迁移。

复核完成时每份 checks 还须提交 `verified_entries`（逐条 index、名称、星期、节次、周次、教师、地点和无固定时段标记，不含备注）。运行时比较原件复核值与当前保存值，周次按集合比较，其余未知值不补猜；不一致先修正 A/B，不能只提交“已核对”说明。此契约仅影响模型工具，正式 HTTP API 不变。协调器在人员返工及人工复核恢复时保留对话与来源覆盖，最新 context 提供当前成果；自动预读记录 actor、mode、来源及工具结果，纳入本机工作日志。已有完成状态不会自动追溯复核，验证新门槛需重新导入或显式返工。

独立复核的 context 只提供课表元数据和课程名称/索引，隐藏首次提取的周次、节次、教师、地点等字段；模型须从原件生成复核值，避免复制首次识别错误。工具日志保留原始复核参数与不一致拒绝结果。名称及索引用于对齐，不构成识别准确率保证。

全批协调通过 `review_consistency` 每批保存最多 5 组结论；context 只展示最多 5 组未核对差异和剩余数量。结论通过实际教师变体、来源阅读门槛后保存事实签名，相关差异变化自动失效；`finish_import` 合并仍有效的检查点，继续要求全部差异有结论。避免在单次最终请求重复输出所有核对记录。新增状态为可选字段，旧人员对象批次恢复时从空检查点开始。

提交操作员复核意见时，如果协调器没有待执行工具，则保留已完成对话与来源覆盖；如果还有旧指令未执行，则重置协调器以取消它们。最新复核意见始终通过当前 context 提供，已核对差异仍按事实签名校验。

人员复核 checks 新增必填 source_person_names：列出本课表原件明确印出的姓名（没有姓名时为空数组，教师对照材料不算本人课表）。有课程的方案若与目标姓名不符，运行时拒绝完成，须纠正身份或将误分派材料交回协调器；仅写文字冲突说明不能放行。已有完成检查点不追溯升级，验收须新建批次。工具协议变更要求前后端同步发布，无新增依赖、环境变量或迁移。

来源复核不一致时，一次返回本课表所有不一致的课程索引及字段名，不透露首次提取值、不修改已存数据，也不降低拒绝门槛，避免逐条报错导致重复整表生成。无新增依赖、迁移或部署参数。

协调器在每批差异核对前自动预读当前最多 5 组差异中尚未读取的来源，复用人员预读、来源覆盖及工具日志；已读来源不重复自动加载。PDF/表格预读未覆盖的页面或范围仍由模型继续读取，different_context 的完整来源门槛保持不变。此优化只消除已知来源的纯读取模型往返，不自动接受核对结论。无新增依赖或迁移。

人员工具新增 amend_timetable，仅按当前人员的课表 key 和原课程 index 局部修正字段，或更新 replace_weeks / unresolved。未提及字段不应用创建默认值，整份候选课表校验成功后才替换，非法索引不留下前半份改动；修正清空旧检查，仍须 finish_person 逐项复核。短课表 key 使用 main / fall 等标识，最多 30 字符。协议需前后端同步发布，无新增依赖、环境变量或数据库迁移。

finish_person 会一次反馈当前人员的课程事实、原件姓名、覆盖范围与缺失说明问题，存在任一问题时不保存完成检查；避免修完一层后才暴露下一层导致重复整表复核。校验规则不放宽，无新增依赖或部署参数。

跨人返工已有课表时，revise_person 直接建立新的独立 verify 上下文，重新读取来源并隐藏已存时段/教师/地点；可局部修正，但仍须提交全表逐字段检查。无课表对象仍先提取。省去重复提取阶段，不跳过来源复核；前后端同步发布，无新增依赖、配置或迁移。

人员复核新增必填 source_student_numbers，填写本人原件明确印出的学号；未印出时为空数组。他人对照材料的学号不纳入。verify 上下文隐藏首次提取的 student_no，有课程方案的原件学号与保存身份不一致时拒绝完成，须回看原件并通过 write_person 修正 information；不以固定学号位数猜测学校规则。前后端工具协议须同步发布，无新增依赖、配置或迁移。已有完成检查点不追溯验证，须重新导入或显式返工。

图片学号在复核指令中要求先裁剪放大表头/学号区域，再逐位核对；这是读取要求，不是可保证识别正确的字符规则。
