# 浏览器本地 Agent 导入

## 用户流程

导入页只有统一材料入口。可拖入 ZIP / RAR / 7z / TAR / GZ、单文件或多文件，无需选择人员、文件类型、学期或部门。一次选择最多 100 MiB，面向约 100 人、500 份材料；解包工具限制每包 500 MiB / 1000 文件，整批材料最多 600 MiB / 1500 文件，嵌套最多 8 层。超过限制明确报错，不静默丢文件。

Agent 自主读取目录、文件名、说明、文本、表格和图片；自主查询已有数据并操作隔离草稿。基础库只处理文件格式，不能依据固定表头、人名正则或模板生成业务数据。Agent 不联网、不执行任意代码或 SQL；只能调用注册工具。模型按后台全局顺序选用支持视觉及工具调用的配置，失败尝试下一项，密钥始终由 Cloudflare Worker 持有。

整理后按组织树展示人员、独立课表、学期/作息、任务与班次，附来源、推断和删改对照。操作员可直接改字段，也可提供自然语言意见继续处理。默认整批确认；可以排除部分人员的变更，剩余内容仍须通过关系校验。正式数据仅在明确点击审核确认后原子写入。

## 执行位置与持久化

- TypeScript 浏览器循环：选择工具、执行本地动作、保存结果、继续模型调用。
- Web Worker：7-Zip WASM、SheetJS、Mammoth、JSZip、MS-DOC/PPT 格式库。工具有 90 秒超时，超时终止对应 Worker。
- PDF.js 和 Canvas：PDF 页与图片读取、裁剪、缩放，图片交给视觉模型。
- IndexedDB：原件、派生图片、草稿、来源、笔记、对话、待执行工具和日志。按管理员 ID 区分批次列表；这是同源本机存储，不是设备级加密隔离。
- Cloudflare Worker：单轮模型协议适配及凭据代理、鉴权、读取业务快照、租约与最终提交校验。
- ECS：沿用现有 SQLite 数据持久化与事务服务。没有 Agent 进程、文档转换服务或解包任务，没有新增计算容器。

连续 8 次工具失败会暂停保留进度，避免无效循环消耗。每轮响应先保存待调用列表，再顺序执行工具并保存结果。刷新或关闭页面会中断运行，重新打开原浏览器可恢复。Web Locks 防止同批次在多个标签页同时运行。上下文交接只在没有未完成工具调用的边界发生：先由同一 Agent 生成交接摘要并归档完整文字历史，再替换活动上下文；失败则保留原上下文暂停。完整草稿、证据、逐材料识别成果和工作笔记保留在本地。原始材料不自动上传到文件服务，只把模型当前需要的文字/图片经凭据代理发送给选定供应商。

**完成或取消后保留 8 小时**。应用打开时和导入页运行期间清理已过期批次与文件；浏览器关闭时无法执行定时任务，到期材料下次打开时清理。未完成草稿保留到处理完成或取消。用户也可以对已完成/取消批次立即清理。本地存储受浏览器配额、隐私模式、用户清除站点数据影响；浏览器数据丢失后不能恢复原件。正式库批次关联与审计长期保留，不含原件或对话。

## 工具与提示词

契约及 system prompt：`src/shared/agent-import/tools.ts`。

- `tree` / `unpack`：查看目录与按需逐层解包。
- `read_document` / `view_image`：分页、分段、工作表/范围读取、原图/PDF 页及裁剪。
- `describe_entity` / `query_records` / `change_record`：完整实体契约及草稿 CRUD，覆盖组织、人员、角色、部门关系、学期、节次、作息、独立课表、历史课程、选课、不可用时段、任务、班次和安排。
- `observe_material` / `read_observations`：逐材料保存识别事实与未确定项，不依赖已创建学期或作息；两份已读材料尚未保存成果时，阻止继续读取第三份新材料。
- `read_history`：分页检索完整工具参数、结果和交接历史；大结果在活动对话中保留摘要与检索键。
- `save_handoff`：仅在交接模式开放，不混入普通业务工具。
- `note` / `read_notes` / `mark_file`：工作记忆与材料覆盖记录；未读取材料不能标记处理完毕。
- `validate_draft` / `finish_review`：结构校验、自查与交付人工复核，均无正式提交权限。

提示词要求查证同名身份、保留多部门关系、每人独立课表、不捏造缺失学号/日期/时间、显示推断与冲突，继续完成可处理部分后集中报告缺项。上传内容作为数据而不是指令，不能改变工具权限。Agent 的自查和结构校验不能证明识别绝对无误；人工复核是最终步骤。

## 文档读取边界

- XLSX / XLS / CSV：单元格坐标、格式化值、公式、样式、批注、合并区域；超过范围分页，不猜业务表头。
- DOCX：正文文本、包内 XML、内嵌图片；PPTX：幻灯片/备注文本、页 XML、图片。
- DOC / PPT：浏览器原生格式库返回结构化块/幻灯片与图片。
- PDF：逐页渲染给视觉模型；图片支持裁剪并放大。
- 文本：支持 UTF-8、GB18030、UTF-16LE；无扩展名的文本也可阅读。
- 无扩展名的 Office/PDF/常用图片通过容器/文件头识别，不据此推断业务含义。

转换/文本读取不承诺完整重现 Office 字体与复杂版式；低清图片也无法凭空还原信息。工具错误、无法读取、缺密码或不支持内容必须留在复核结果，不能视为无课程。ZIP 嵌套、合成 DOC/DOCX/PPT/PPTX/XLS/XLSX/CSV/PDF/PNG 已有浏览器验证；不声称所有历史变体、加密方式和损坏文件均可读。

## 业务数据与提交

`schema/rota.yaml` 增加人员班级/专业，以及 `TimetableProfile`、`TimetableEntry`、`TimetableEvent`。增量迁移 `0005_browser_agent_import.sql` 另外维护批次、锁、提交断言及修订号等运行时表。

- 独立课表以个人为单位，关联学期与作息，明确周次/星期/节次；展开成真实时间段。支持同学期多套作息。
- 全局节次保留，已有共享课程兼容。新独立课表在可用性网格中按时间重叠标记，排班额外按绝对时间查询，因此全局节次以外的晚课同样阻止派班。
- 未识别出占用的时间按空闲；资料不完整必须在复核时提示。
- 已有人员与部门关系默认保留；空学号允许。新增或修改的数据都要附来源及推断标记。
- 人员页的独立课表入口支持修正与删除；通过同一校验/事务路径提交。没有“撤销整个导入批次”功能。

浏览器上传结构化差异而非 SQL。服务端阻止新增约束冲突，已有历史问题不阻塞无关导入；重新校验字段白名单、原值、外键、重复记录、学期/周次/节次和班次冲突；生成 SQL 仅来自共享实体契约。原子提交包括业务变更、派生占用、必要的公平投影、批次关联和审计。批次内容哈希保证重复确认幂等，失败全部回滚。

相关实体及依赖项使用 180 秒租约；工作界面每 45 秒续期，事务触发器也约束普通 CRUD 路径。租约过期后释放；恢复时重新读取快照，冲突变更交由 Agent 重新协调。共享学期等实体的依赖闭包可能锁定较多记录，以保护现有引用。提交在同一事务内复核修订号和全部租约，避免校验与写入之间的数据变化。

## 验证

- `pnpm check`：类型、真实 SQLite 的原子性/并发锁/幂等/多作息冲突/100 人批次与模型协议测试，以及原有测试。
- `pnpm build`：前端、文档 Worker、WASM、PDF Worker 与 API 构建。
- `pnpm test:agent-browser`：独立静态测试服务，API 全部拦截，不访问生产；真实浏览器文件工具、刷新恢复、审核边界、格式读取与 8 小时清理测试。
- `test/fixtures/import` 全为合成材料，无真实人员资料。LibreOffice 仅用于生成旧格式测试样本，不是产品运行依赖。

常规测试不调用真实供应商，也不提交生产业务数据。另提供显式启用的真实模型隔离验收，见下文；模型识别准确率不能由模拟响应测试代替。

## 随包许可

`public/licenses/agent-import` 包含文件读取库与模型 SDK 的许可及来源，随静态站点发布。7z-wasm 使用 LGPL 与 unRAR 附加限制，未修改其分发代码；WASM 保持独立可替换资源，来源与构建说明见随包 README。

SQL 批事务在提交时校验外键（`defer_foreign_keys`），允许同批新增上级、迁移子记录及删除旧上级；最终悬空引用仍使整个事务回滚。

## 长任务稳定性与选型依据（2026-11-04）

实测日志出现数十分钟重复读取、反复查询实体契约、仅产生一条学期草稿。旧执行器用 `slice(-12)` 截断消息后再删除开头 assistant/tool，可能清空有效识别上下文；保留原件并不等于保留识别成果。这是本次修复的主要根因。503 的真实上游来源无法仅凭旧日志追溯，旧客户端将所有 503 指向迁移的提示没有证据支持。

研究后保留已有 AI SDK 协议适配与浏览器执行边界，没有换成服务端 Agent：

- [Anthropic 长任务 harness](https://www.anthropic.com/research/effective-harnesses-for-long-running-agents)：借鉴增量成果、可恢复工作状态和交接机制。
- [Anthropic 上下文工程](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)：借鉴压缩、结构化笔记与按需检索，避免无限堆叠工具输出。
- [Deep Agents summarization 实现](https://github.com/langchain-ai/deepagents/blob/main/libs/deepagents/deepagents/middleware/summarization.py)：借鉴完整历史外置、摘要留在活动上下文的设计；不直接引入 Python 服务。
- [Deep Agents JS 浏览器兼容性讨论](https://github.com/langchain-ai/deepagentsjs/issues/834)：存在浏览器运行时适配问题报告，不能假设更换框架就自动满足本项目浏览器边界；本次复用已验证的协议适配层。
- [Pi compaction 文档](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/compaction.md)：参考持久交接与恢复信息，而非简单删除历史消息。
- [AI SDK 调用设置](https://ai-sdk.dev/docs/ai-sdk-core/settings)：继续使用现有供应商协议、工具 schema、usage 与取消信号；执行期限与重试边界由本项目显式控制。

具体机制：

1. 原 `rota-agent-import` 数据库版本不变，兼容既有批次。新增 `rota-agent-history` 数据库承载完整文字历史，避免旧标签页阻塞原数据库升级。草稿与待归档检查点先原子保存，归档按键幂等；恢复时重放未归档检查点。历史按批次/时间游标分页，不每次载入所有历史。
2. 每份材料用 `observe_material` 保存来源关联的识别事实和未确定项。读取不等于完成；标记完成前需保存未记录的识别成果。缺少日期/作息仍能保存事实并继续其他人员，不能根据最大课程周次伪造总周数或首周日期。
3. 活动文字约 48,000 字符或消息超过 100 条时，在工具调用完整边界进行交接。摘要和完整历史归档成功才收缩上下文。超过 12,000 字符的工具结果外置，模型可按 key/offset 读全文。交接摘要不会代替原件或持久识别成果。
4. 尚未保存成果的材料保留整图及最近两张局部图；保存后可用来源引用替换图片字节，原件仍可裁剪重读。默认图像缩放改为 1，避免无意义的 1.5 倍放大；PDF 初始页面渲染仍保留 1.5 倍。尚未得到模型响应的图片不提前清除。
5. 连续 6 轮没有新增草稿、识别成果或文件覆盖进度时注入纠偏提示，12 轮暂停并保留工作。仅成功执行查询不算进展；连续 8 次工具错误仍暂停。模型可在结构问题无法解决时交付问题清单，复核界面和最终提交校验继续阻止不合法草稿入库。
6. 每批成功供应商优先复用；失败项短暂冷却。记录真实模型 ID、各次尝试耗时/HTTP 类别、tokens 与请求编号。进度区显示当前阶段和等待秒数；展开后可查看识别成果与完整工具历史。最近 200 次请求诊断随草稿保存，完整模型/工具/失败请求历史另行归档。工具记录包含参数、全文结果和执行耗时，不仅展示截断片段。
7. 原件、识别成果、交接、历史和诊断均随完成/取消批次在 8 小时到期后清理；关闭浏览器期间到期，下次打开清理。未完成草稿不因升级清空。旧版本已经截掉且没有保存的事实无法恢复，只能重新核对来源。

### 验证边界

`pnpm test:agent-browser` 覆盖真实 Chromium + IndexedDB + 本地工具：30 份合成材料、多次交接、刷新恢复、全文历史检索、交接失败不丢上下文、未归档检查点恢复、停滞暂停、两份材料写入保护、503 有界重试，以及有结构问题的草稿能复核但不能提交。模型输出为受控响应，测试执行器恢复与隔离，不证明真实模型能够无误识别所有课程。现有旧 Office / PDF / 图片 / 嵌套压缩包工具测试继续保留。

此阶段没有新增环境变量或数据库业务迁移；后续真实材料回归新增 OCR 与兼容协议依赖，见下一节。浏览器专项测试配置显式设置仓库根目录为工作目录，可直接从项目脚本启动。发布仍需要前端与 Worker 同版本；不能只更新前端就使用新的交接工具协议。真实批次识别质量、供应商速度和该次 503 的具体来源需要新版运行日志验收，不将合成测试结果当作生产成功证明。

## 实际压缩包回归与结构化方案

`save_timetable` 接受 Agent 明确填写的人员、部门 ID、课程名、星期、节次及展开后的周次，原子暂存于本地草稿。未提供学期/作息时仍保留并展示全部课程；提供有效引用后生成 `timetable_entry`。`read_timetables` 返回方案索引或完整内容。基础工具不从文件名或文字中推断字段。多图合并由 Agent 决定，替换方案时必须带齐全部课程，不能偷偷替换归属人。未绑定方案以及尚缺定位信息的课程阻止正式提交，排除相应人员后可提交其余完整部分。

代理逐个校验 AI SDK 返回的调用名称、参数与调用 ID。SDK 可能将畸形工具参数转换为错误结果而不抛异常；此时整轮拒绝并尝试下一个供应商，不将坏响应写进浏览器历史。旧版本恢复时归档旧对话后重建活动上下文，保留草稿、笔记、识别成果和原始材料。

HTML 形式的 `.xls` 按 BOM / charset 声明解码；无声明时先验证 UTF-8，再回退 GB18030。CSV 和文本亦支持显式编码覆盖。只修复格式读取，不根据固定业务表头生成课表。

显式运行真实模型验收：

```sh
pnpm test:agent-live /path/to/archive.zip /private/output-directory /path/to/snapshot.json
```

此命令使用真实浏览器运行器、解包/文档工具与当前配置的模型，会发生模型调用费用。服务端凭据由 Node 进程读取，不进入页面。业务 API 被隔离：允许读取供应商配置，拒绝数据库写入，禁止 apply/cancel；快照由可选 JSON 提供。输出目录权限为 0700，包含个人材料、完整日志、草稿及模型调用记录，必须置于仓库之外并在验收后清理。`ROTA_DATA_CONFIG` 可指定凭据配置文件；默认读取本机 Rota 配置。默认最长 20 分钟，`ROTA_LIVE_MAX_MS` 可覆盖；到时停止并保存进度。命令不会把完成阅读等同于正确导入，仍须核对课程、身份、周次与来源。

运行器只在已读材料成果保存后才整理上下文；未保存材料保留整图和最近两张局部图（最多两份材料、六张图）。普通笔记工具由 Agent 显式标记材料类型；已识别课表的文字观察不会解除保存门槛，须继续写结构化方案。`describe_entity` 返回输入契约，自动生成的默认字段不再误列为必填。Excel 工作表支持独立 sheet 或标准带表名的 range，并按实际工作表记录阅览页号。

参考：[AI SDK 工具错误与修复](https://ai-sdk.dev/docs/ai-sdk-core/tools-and-tool-calling)、[generateText 返回契约](https://ai-sdk.dev/docs/reference/ai-sdk-core/generate-text)。本项目额外检查已安装 SDK 实际返回的 invalid 调用，不能只依靠 try/catch 或文档概述。合法 JSON 的参数错误通过 `validationError` 回到浏览器，拒绝执行并将具体错误反馈同一 Agent；只有未知工具、损坏 JSON 等协议错误才切换供应商。SDK 合成的错误工具响应不与浏览器响应重复入库。

兼容端点使用 `@ai-sdk/openai-compatible` 2.x（匹配 AI SDK 6），保留并回传供应商的 `reasoning_content`；不能用只面向 OpenAI 协议的适配器静默丢弃它。MiniMax M3.1 默认思考强度由代理显式设为 `medium`，管理员 `params.reasoning_effort` / `reasoningEffort` 优先；该调整仍须以真实材料质量回归为准。[MiniMax 官方参数说明](https://platform.minimax.io/docs/guides/text-generation)。损坏 JSON、未知工具名及截断输出不会进入活动历史；可修正的参数错误作为工具反馈保留。连续无效动作或没有成果时先尝试其他已配置模型，仍无进展才暂停。

`ocr_image` 使用 Tesseract.js 在浏览器本地识字，返回文本、行坐标及原始截图；OCR 可能错字，不参与业务判断。WASM、Worker 和中文/英文语言数据均来自锁定依赖，通过 `pnpm assets:ocr` 复制到忽略 Git 的 `public/vendor/ocr`，开发、构建与浏览器验收命令会准备这些资源，运行时不使用第三方 CDN。语言数据为构建依赖，须在构建阶段安装 devDependencies。`tesseract.js` 的募捐 postinstall 显式禁用，运行本身无需该脚本。

复杂课表可以分段保存：`save_timetable` 的 append 模式追加明确字段，replace 模式替换全部方案；部分读取时不能标记源文件已完成。`bind_timetables` 只需明确列出方案和已确认学期/作息 ID，无需重复抄写全部课程。课程重叠提示只检查明确周次和节次，供 Agent 回看原图，不自动删课或裁决真实冲突。待绑定课程也支持人工直接修改字段。

来源校验接受已读取文件及目录树中确实存在的目录，允许把目录名作为推断依据；标记材料完成仍需读取实际文件。图片与 OCR 共用每三个视图的部分保存检查点，保存已识别课程后继续读取，不要求整张识别完才落草稿。OCR 文本只在工具结果中保留一次，随图片附带的说明仅含坐标和尺寸。

真实验收可用独立的人工标注进行逐项比较：

```sh
node test/live/compare.mjs /private/result.json /private/expected-person.json
```

expected JSON 包含 `person`（姓名及可选学号等明确身份字段）、`scheduled`（name、weekday、period_from、period_to、weeks）及可选 `unscheduled` 课程名列表、`organizationIds` 部门归属。无时段课程须实际保存在课程方案中，仅在未决事项里提及不能算通过。标注必须由原件人工核对，不能用被测模型的输出生成。比较器将明确课程展开为课程/星期/教学周/节次多重集合，同时报告身份、名称和占用遗漏、额外占用、重复记录；默认只规范化 Unicode、空格及英文大小写；可选 nameAliases 显式列出经原件核对的同名格式变体（例如课程代码前缀），不将近义课程名视为正确。由开发 Agent 独立转录的标注必须注明来源，不能称为操作员已验收。比较器只用于验收，不参与导入业务处理。人工标注、运行结果及个人材料均留在仓库外。

达到交接阈值却仍有未保存材料时，执行器阻止打开下一份材料，要求先持久化当前事实；避免某份旧文档长期阻止交接，导致后续每轮上下文不断增长。保存失败仍保留原图和原始响应，不能把“工具被调用”当成“草稿写入成功”。

伪装为 XLS 的 HTML 导出还通过 parse5 返回 `outsideTables` 文本与分页信息，覆盖表格外说明、页脚课程等；不执行 HTML 脚本或加载外部资源。表格单元格仍由 SheetJS 读取，业务解释由模型完成。[parse5 官方说明](https://parse5.js.org/)。

## 同 Agent 逐人核对

初步保存不等于核对完成。材料保存完成且没有悬空读取时，浏览器切换到当前人员的聚焦复核上下文，保留主任务对话作为可恢复状态。仍由同一导入 Agent 和现有供应商顺序执行，重新读取源文件全部页面，逐项比对课程名、星期、节次、周次、跨页及附注。`revise_timetable` 可按索引只改字段、补条目或明确删除重复项，避免整表重写。`confirm_timetable_check` 只有本次已重新读取全部来源页时才能成功；保存当前方案签名，修改后核对失效。签名只覆盖源事实，学期/作息绑定仍由结构校验约束。

核对上下文、来源页覆盖和主任务对话随批次检查点保存，刷新后继续；完成后归档复核记录再恢复主任务。`finish_review` 和正式提交检查均阻止未经逐人核对的方案。操作员对已经核对的方案直接修订课程或身份字段时同步更新草稿与签名，不由旧方案覆盖人工意见。此机制降低漏读风险，不将模型确认冒充人工作业验收或绝对正确证明。

单轮业务工具输出上限为 16,384 tokens，交接摘要为 4,096 tokens，避免较长课表仅因原 8,192 tokens 上限被截断；仍有请求时限，截断响应仍拒绝进入历史。

达到未保存读取阈值时，代理进入 `checkpoint` 工具集合，只允许持久化成果与必要查询；保存完成后恢复读取，减少模型重复调用被禁止读取工具的空转。

`revise_timetable` 同时允许增量修订 `term_name` 与除 ID 外的人员身份字段。单周截图中明确第 N 周的课程保存为 `weeks: [N]`，不能误用 null 丢掉已知占用，也不能扩展成整学期。未显示的后续节次继续待定。

逐人复核的 `verify` 模式只提供原件读取、当前课表查询/修订、核对确认与必要历史读取；避免在复核过程中转向全局笔记和通用业务查询。核对签名包括学期标题，标题修正也纳入复核版本。

隔离真实模型诊断可设置 `ROTA_CAPTURE_PROVIDER_RESPONSES=1`，仅将供应商返回的工具调用与正文写入指定私有输出目录（可能包含人员信息），不记录请求头或密钥，不进入 Git。默认关闭。

对照模型验收可显式设置 `ROTA_LIVE_PROVIDER_ID`、`ROTA_LIVE_MODEL`、`ROTA_LIVE_KIND`、`ROTA_LIVE_BASE_URL`，仅在测试进程中替换指定配置，并强制复用凭据的原有 origin；不会修改全局配置。结果必须与沿用全局模型顺序的验收分开报告。计时同时输出本次进程耗时及从批次创建到结果的累计墙钟时间，恢复测试不能冒充全新单次性能成绩。

## 完整阅读覆盖与表格图片

文件读取返回基础覆盖区域。工作表按 `extent` 与实际返回 `range` 累积矩形覆盖；文本按总长度和 offset 累积分段；图片/PDF 按原始坐标累计区域；表外附注单独累计。单张图片只接受 page=1，图片内多页排版使用像素 crop。只有完整覆盖才能将该页记为读完，旧的“打开过一页”记录不作为新一轮复核证明。逐人复核独立维护新覆盖记录，最后一列或首段遗漏会阻止确认。覆盖校验不判断哪些单元格属于课程。

`render_sheet` 使用 SheetJS 的明确坐标与合并信息构造安全 DOM，再由 [html-to-image](https://github.com/bubkoo/html-to-image) 在浏览器渲染 PNG；显示行列坐标和表外文本，不声称重现 Excel 原始打印样式。不执行上传 HTML、脚本或外链。支持 sheet/page/range；大表须分块。对电子表格调用 `view_image` 也会使用该网格渲染，像素 crop 请求会提示改用单元格 range。

交接阶段指定 `save_handoff` 工具；错误调用保留上下文并反馈修正，受无进展次数限制，不直接丢弃上下文。真实验收批次采用独立的供应商会话 ID，恢复同一输出目录时保持稳定，避免不同测试复用同一会话标识。

主任务状态显式提供 verification=null 和每份方案的 sourceChecked，普通工作阶段不开放确认复核工具，避免旧交接笔记触发重复确认。返回模型的课程条目附显式 index，增量修订无需重新数数组位置。复杂周次原文保存在条目 note，由模型展开并核对，系统不使用业务规则解析。

文档、图片/OCR、表格图片和课表详情的工具输出不再经过通用预览截断。文件读取器自身的 range/offset 分段与覆盖记录保持一致，防止原件尾部已计入“读完”却未实际发送给模型。其他大结果仍可通过 historyKey 读取完整记录。

无进展冷却只用于选择备用模型；没有其他可用模型时保留一次现有模型的纠错机会，仍受 12 轮无进展和连续工具错误上限约束，不把唯一模型冷却导致的空集合误报为模型未配置。增量修订分别说明更新/删除冲突、重复索引、越界，错误不会改变草稿。

已有非空课表不能通过 save_timetable 的空 entries 整表覆盖；只修订身份/标题使用 revise_timetable，删除课程须显式列出 remove 索引，防止恢复上下文后把已识别课程清空。
