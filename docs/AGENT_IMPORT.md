# 人员对象导入

## 业务链路

拖入压缩包或多份材料 → 协调器识别人员与公共日历 → 实例化 m 个 PersonWorkspace → 有限并行子智能体填写并核对每人的信息 A / 课表 B → 按 A 匹配已有人员 → 生成 B 的范围覆盖差异 → 人工复核 → 原子提交。

每人可以有多份来源、多份学期课表；一份材料也可分派给多人。目录名只是身份线索，不自动作为姓名。明确无固定时间、未知时间、缺失本人课表分别保留。公共学期与作息独立维护，部分日期/钟点可保存，缺项不能猜造。

## 执行架构

- `shared/agent-import/person-workspace.ts`：人员对象 A/B、来源、状态、检查和身份匹配契约。
- `client/agent-import/person-runner.ts`：协调器与人员子智能体；默认最多 3 个人员并行。协调器发现完成后启动人员任务，人员全部完成后汇合协调公共事实。每人最多 32 次模型请求/次运行，协调器最多 60 次；连续 6 次工具错误暂停当前对象。
- `client/agent-import/projection.ts`：唯一共享草稿写入者。子智能体只维护自己的对象，完成汇合后程序生成业务差异。
- `client/agent-import/state.ts` / `store.ts`：对象状态与 IndexedDB 持久化。模型响应的待执行调用先保存，再执行；完成调用与对象成果同一快照保存。单批保存串行化，避免并行成果相互覆盖。
- `client/agent-import/runtime.ts`：人工编辑、身份选择、检查、租约和正式提交。
- Worker `llm/agent.ts`：现有 AI SDK 多供应商单轮凭据代理，只提供当前阶段工具，不执行业务写入。

模式为 `discover`、`person`、`verify`、`reconcile`。已移除旧版 work/compact/checkpoint 循环、全局识别笔记、模型生成交接、通用实体 CRUD 与逐条建库工具。旧版检查点不自动转换为已核对人员对象；原件和结果仍保留供查看，新执行需要用原材料创建新批次。已经提交的审核报告继续可下载。

## 工具与对象权限

协调器可用 tree/unpack、阅读工具、dispatch_people、save_calendars、mark_material、finish_discovery；全批协调可重新分派或移除重复人员对象、revise_person、save_calendars、finish_import。

人员子智能体只有 read_document/view_image/render_sheet/ocr_image、write_person、finish_person。write_person 绑定当前人员，不接受他人对象 ID；A/B 可一次批量写入，长课表按 key 追加。对子智能体未分派的文件和公共日历写入均拒绝。Office 派生附件继承父来源的阅读范围。

每个人提取完成后自动进入独立 verify 上下文，重新预读来源；checked_entries 必须覆盖最终全部课程，字段检查包含身份、课程时段、教师地点、日历和完整性。结构覆盖来自读取工具的实际坐标；读完文件不等于材料提供完整课表。跨人教师差异继续要求逐变体说明，different_context 需要协调器回看相关来源。

程序仅处理文件格式、来源坐标、明确字段比较和时间展开；不按固定表头或姓名正则猜测业务含义。所有材料作为数据，不得扩大工具权限。

## 匹配和覆盖

学号和姓名唯一一致可匹配；无可用学号时，姓名与班级唯一一致可匹配。仅同名、同学号不同姓名或多个候选保持身份待确认，界面可选择已有人员或明确新建。审核页可修订本批新增人员与部门，已有 A 保持原值；课程和日历使用各自对象编辑器。现有人员保留信息 A，新人创建 A；两种情况都应用 B。包内重复人员对象必须先协调合并。

完整课表只替换该人员对应学期的独立课程及本人旧选课关系，不删除他人的选课或共享课程。部分材料必须明确 replace_weeks，仅替换这些教学周，保留其他周次。部分覆盖遇到旧共享课程选课时明确阻止，需先在课程管理中处理，不擅自删除整学期选课。零课程缺失方案保持未绑定，不清空已有课表。多个 B 在同一学期的覆盖周次不能重叠，应先合并来源。

公共日历完整后程序调用已有 stageCalendar / stageTimetable 生成个人课表、无固定时段课程与实际占用。人工修改课程、身份、日历或导入范围后，全批确认失效，需要继续协调核对再提交。缺少日历、未完成人员、身份冲突或非法关系阻止提交；识别完成但缺少日历仍能进入人工复核。

## 恢复与材料处理

原件、对象、对话和工具历史位于当前浏览器。模型需要的文字/图片经 Worker 发给已配置供应商，密钥不下发。ECS 只存正式业务、批次与审核记录，不运行 Agent 或文档转换。

关闭/刷新会中断执行，重新打开原浏览器恢复对象和待执行调用；已完成人员不重跑。暂停会等待已发出的请求返回并保存，随后停止执行待调用工具。Web Locks 阻止同批并行运行及运行中的人工修改；旧标签页的过期草稿会拒绝写回。复核阶段失败后继续复核，已完成人员不重提取。上游已经完成但本机尚未保存时可能重复调用模型，不能保证上游计费恰好一次。正式提交保留现有幂等和事务校验。

网络错误最多三次退避重试，其他可重试模型错误最多一次；额度耗尽或超过 30 秒的 Retry-After 不立即重试。文件读取在本机排队，复用现有解包、SheetJS、Office、PDF.js、Tesseract 和表格渲染实现，避免共享来源覆盖记录发生竞争。图片传输仍保留预算和来源。

一次上传 100 MiB；展开批次最多 600 MiB / 1500 文件，嵌套最多 8 层。ZIP/RAR/7z/TAR/GZ、现代与旧 Office、文本、PDF 和常用图片继续支持。OCR WASM/语言资源通过 `pnpm assets:ocr` 从锁定依赖准备，同源加载。格式错误和低清内容显式报告。

完成或取消后原件保留 8 小时；应用打开时清理，浏览器关闭时到期的材料下次打开清理。未完成批次保留供恢复。浏览器存储被清除后不能恢复原件。

## 真实模型隔离验收

```bash
pnpm test:agent-vertex /private/input.zip /private/output /private/snapshot.json
# 或使用已配置供应商（读取本机生产配置，但业务写入拦截）
pnpm test:agent-live /private/input.zip /private/output /private/snapshot.json
```

输出目录必须在仓库之外，包含个人材料、对象检查点与诊断。默认最长 20 分钟，可用 ROTA_LIVE_MAX_MS 覆盖。使用相同输出目录可恢复已保存的新版进度；恢复计时不作为全新运行成绩。ROTA_VERTEX_PROJECT、ROTA_VERTEX_LOCATION、ROTA_LIVE_MODEL 可覆盖测试参数；本机 gcloud 凭据只在 Node 测试代理使用，不传浏览器、不修改生产供应商顺序。ROTA_DATA_CONFIG 可指定本机服务凭据配置。脚本禁止正式 apply/cancel 和配置写入。

核对同一原包的身份、课程星期/教学周/节次、教师地点、无时段课程及缺失信息。人工标注不注入被测模型。新增架构必须重新运行实际材料验收，不能沿用旧架构的 34 分钟参考值宣称已经提速。

复核工具 `finish_person.checks` 使用显式数组，每项包含课表 `key` 和字段核对结果；不使用动态键字典，以确保 Google 工具 schema 保留核对字段。对象持久化与正式审核报告仍按课表键保存检查结果，无新增依赖、环境变量或数据库迁移。
